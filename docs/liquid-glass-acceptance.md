# 液态玻璃第一阶段人工验收

## 范围与运行方式

本轮覆盖全局底部导航、共享 MiniPlayer、公共底部弹窗，以及首页／在线搜索／本地搜索／设置中的共用搜索控件和设置页玻璃导航。播放器控制按钮的点击区和语义标签也纳入检查；播放器全屏背景、歌词主体、独立歌词悬浮窗及各播放器风格的视觉表现保留原设计。

导航和 MiniPlayer 以官方 [Apple Music 样例](https://github.com/sdegenaar/liquid_glass_widgets/blob/main/example/lib/apple_music/apple_music_demo.dart) 为材质基准。带全局播放控件的页面与玻璃设置页使用 GlassScaffold。导航为可收起的 GlassTabBar.minimizable；高对比度、减少动态效果、大字体或窄屏时不收起。桌面根内容与 MiniPlayer 共用 1120 最大宽度；设置首页在宽屏分两列，设置正文最大宽度为 720。普通玻璃控件使用 standard，仅持久导航和 MiniPlayer 可请求 premium。

所有质量模式保留向 minimal 降级的能力。高质量模式从 premium 上限开始，普通控件仍请求 standard；标准及省电模式的上限为 standard，低质量及关闭为 minimal。除低质量和关闭外，可以恢复到所选上限。省电模式的搜索、弹窗等普通控件使用不透明／Material 表面。

公共弹窗采用原生 GlassModalSheetScaffold 的单个 medium 停靠档位，可向下关闭。歌曲／下载菜单最高约 72%，选择列表约 80%，队列与长正文约 88%；短面板可按内容撑高。队列没有中间展开档位，isScrollControlled 不代表默认全屏。材质跟随当前主题；输入框获焦时内容避让键盘。关闭玻璃控件后使用 Material 弹窗。

默认运行（使用实际设备 ID 替换 `<device-id>`）：

```sh
flutter run -d <device-id> --dart-define-from-file=.env
```

性能验收请使用真机 profile 构建：

```sh
flutter run --profile -d <device-id> --dart-define-from-file=.env
```

关闭玻璃、对比原皮肤表面：

```sh
flutter run --profile -d <device-id> --dart-define-from-file=.env --dart-define=ENABLE_LIQUID_GLASS=false
```

开关为构建参数，变更后完整重新启动应用，热重载不会更新它。无开关设置时默认开启。初始化失败时主应用仍启动并回退；独立歌词悬浮窗不初始化本库。

## 操作与预期

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 无播放队列启动，切换首页和我的，多次返回各分支 | 底栏可点击、皮肤图标和玻璃选中胶囊正确，无重复指示器或底栏；MiniPlayer 保持原来的空队列隐藏行为 |
| 2 | 播放歌曲，观察底栏和 MiniPlayer；切换亮色/暗色及不同壁纸皮肤 | 颜色、文字、图标可读；无白块、黑块、边框错位；滚动时能看到内容经过底部玻璃后发生模糊/折射；列表最后一项可完全滚出底栏遮挡区域。纯色背景折射不明显是正常现象 |
| 3 | 应用设亮色、系统设暗色，再反向组合；打开歌曲菜单后切换应用主题 | 弹窗实时采用应用主题：浅色配深色文字，深色配浅色文字；把手、图标和禁用项可辨认；按压高光保留 |
| 4 | 打开专辑/歌单等详情页，操作底部 MiniPlayer | 详情页共用的 MiniPlayer 正常显示；点击封面/标题打开播放器，返回后状态同步 |
| 5 | MiniPlayer 播放/暂停、左右滑动切歌、连续切歌；切换电台模式 | 播放行为保持原样，标题和封面及时更新；电台模式不出现队列入口 |
| 6 | 从 MiniPlayer 打开队列，滚动长列表，选歌，再打开并向下关闭 | 队列一次打开到约 88%，没有中间停靠档位；无高度溢出、双层模糊或滚动冲突；选歌和关闭正常 |
| 7 | 打开在线歌曲菜单、下载菜单和移动端选择面板，分别点击遮罩、向下拖动把手、系统返回 | 各入口按统一高度或内容撑高打开，长菜单能滚动访问末尾操作；结果正确返回，关闭后页面仍可交互，播放不被中断 |
| 8 | 在首页/我的及详情页输入框唤起键盘，再关闭；测试涉及输入的操作面板 | 全局底栏/MiniPlayer 不随键盘异常跳动；页面原有键盘避让行为保留；无新遮挡或溢出 |
| 9 | 切换皮肤、内容背景开关、单色模式，再打开弹层 | 皮肤变化及时生效；歌曲列表/内容卡片没有被额外玻璃化；单色模式仍有效 |
| 10 | 关闭液态效果后重复 1、5、6、7 | 使用原有皮肤表面，操作与返回值一致；启动不进行液态玻璃预热 |
| 11 | 打开系统减少动态效果、高对比度（平台支持时） | 无额外液态动画；高对比度下控制表面不透明且可读；系统设置变化能够正确响应 |
| 12 | 开启 TalkBack/VoiceOver，逐个访问导航、播放按钮、队列和弹层关闭把手；macOS 使用 Tab/Enter | 标签、焦点、激活和关闭操作正常；焦点不被玻璃表面拦截 |
| 13 | 在线、本地及设置搜索输入、提交、清空；桌面用 Tab 移动焦点 | 搜索框高度、圆角与图标对齐一致；清空后保留焦点；焦点反馈可见；本地搜索点开即输入，返回先退出搜索 |
| 14 | 窄屏、大字体下操作播放器、本地列表和下载任务 | 图标按钮点击区至少 48×48；播放器核心操作有明确语义标签；文字不被固定高度裁切，控件不会整体缩成小点击区 |
| 15 | 桌面打开本地音乐、下载、搜索和设置，并调整窗口宽度 | 根内容与 MiniPlayer 对齐，最大宽度 1120；设置首页宽屏两列、窄屏单列，正文最大宽度 720 |
| 16 | 在高质量、标准、省电模式下执行性能对比 | 普通控件不请求 premium；质量仍可降级到 minimal；省电模式普通控件不折射；记录实际帧耗时，不能以配置断言代替测量 |
| 17 | 下载菜单选择删除文件并取消／确认，清空播放历史并取消／确认 | 危险项使用危险色，取消不删除，确认后才执行；文件影响范围明确 |

## 性能与平台记录

Android、iOS、macOS 分别执行上述适用步骤，并至少在一台性能较低的 Android 真机检查。记录设备、系统版本、屏幕刷新率、应用主题、皮肤、玻璃开关及是否 profile 构建。

在相同设备和相同歌曲/皮肤下，对比开启与关闭玻璃时：连续滚动首页 30 秒、快速切歌 10 次、队列开关 10 次、播放动态背景并切换回首页。用 DevTools Performance 观察 UI/raster 帧耗时；60 Hz 对应约 16.7ms 帧预算，120 Hz 对应约 8.3ms。若开启玻璃后出现持续掉帧、明显发热、黑块、闪烁或点击延迟，记录对应场景和录屏，判为未通过，不以自动降级开关代替真机测量。

人工验收由项目负责人执行。组件测试覆盖布局、回退、高对比度和弹层返回行为，不能证明真实 GPU 的折射效果、帧率或读屏体验。记录结果建议：`平台 / 设备 / 步骤编号 / 通过或失败 / 截图或录屏 / 备注`。
