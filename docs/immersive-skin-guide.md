# 沉浸式皮肤制作指南

本指南用于在 HE Music 中制作新的应用全局沉浸式皮肤。用户下次只需指定“风格 / 场景 / 氛围”，制作方即可沿用这里的要求，完成从美术到运行资源、真实界面及验证的交付。

本文记录已经确认的通用偏好；具体主题的元素、颜色和参数应重新设计。森林秘境是实现参考，不是所有新皮肤的视觉模板。用户当次明确提出的要求优先；界面结构同时遵循 [仓库指南](../AGENTS.md)、[界面风格设计决策](adr/0010-use-sdk-interface-styles.md) 和 [界面验收指南](interface-style-acceptance.md)。

## 1. 目标与默认范围

目标是让用户进入一个有完整美术语言、环境动态和空间层次的音乐世界。背景、控件、图标与运动应像属于同一部动画电影或同一个场景，而不是各自独立的装饰。

默认覆盖首页、搜索、资料库、我的、设置、普通内容详情、MiniPlayer 和底部导航。普通页面应延续场景与材质，不在切页时突然回到无关的白底或黑底。弹窗优先保证阅读与操作清楚，再用配色和细节延续主题。

全屏播放器已有独立的封面、背景、歌词及样式配置；除非用户明确要求，不将全局皮肤强行覆盖到这些配置。

已经确认的偏好：

- 需要整体设计，不能以“换壁纸和主题色”作为完整交付。
- 环境动画默认使用 Rive，沿用应用已有播放链路；动效应在实际手机界面中看得见。
- 明暗模式分别设计环境表现，动效对象符合场景、时段和光照逻辑。
- 壁纸皮肤的 MiniPlayer 和底部 Tab 保留带底色的半透明磨砂，让场景和滚动内容能够透出。
- 保持音乐内容为主体，不给首页强加主题宣传区、欢迎横幅或额外引言。诗意文案可以放在皮肤介绍里。
- 需要时可以修改共享组件与皮肤模型，但应继续复用现有业务页面、路由和状态。
- 控制素材制作成本：同类位图优先整套图集制作，图标和可程序化装饰优先使用矢量。

## 2. 先定义世界，再设计页面

动手前先形成简短的主题说明，信息能从用户描述推断时直接推进；只有会改变方向的关键缺项才需要澄清。用户没有要求多方案时，不必反复等待阶段确认。

| 设计项 | 需要回答的问题 |
| --- | --- |
| 场景与情绪 | 用户身处哪里？希望感到安静、梦幻、温暖、辽阔还是有活力？ |
| 美术语言 | 手绘动画、柔和水彩、复古科幻、几何插画等，轮廓与细节密度如何统一？ |
| 空间与光源 | 远景、中景、近景是什么？光从哪里来？文字与主要操作放在哪里？ |
| 日夜关系 | 是否为同一地点的不同时间？白天和夜间各自最有辨识度的变化是什么？ |
| 材质与图标 | 控件像什么材质？线条、圆角、纹理和强调色如何回应场景？ |
| 环境动态 | 哪些对象会动、为何而动？哪些动态在手机裁切后仍可见？ |

把方向写成一句能够指导实现的话，再确定有限的视觉母题。例如“晨光穿过林间、树叶随风飘落的手绘森林”，其母题可用于叶形图标、细叶脉、暖色控制表面和自然风向。换成海底或太空时，应重新选择相应母题。

## 3. 让五个部分共同组成皮肤

| 部分 | 设计要求 | 实现建议 |
| --- | --- | --- |
| 主场景 | 有构图、光照、空间层次和日夜关系；预留阅读区 | 高质量静态位图承担主要画面，避免把全部细节做成持续动画 |
| 环境层 | 通过少量可见运动赋予空间生命感 | 透明 Rive 叠加，近远景使用不同速度、幅度和相位 |
| 组件材质 | 搜索、列表、设置、播放控制与背景属于同一世界 | 共享表面中的主题色、轻纹理、边缘和适量透明度 |
| 图标语言 | 高频入口有主题辨识度，同时立即可认 | 原创 SVG 或 SDK 图标；统一轮廓、线宽、视觉重量 |
| 内容与交互 | 信息清晰，播放、搜索与浏览手感稳定 | 保留布局层级、点击范围、焦点、状态及返回语义 |

主场景负责氛围，环境层负责运动，控件负责清楚地承载信息。避免把同一装饰在背景、卡片和图标里重复堆满。大面积图像不应画入按钮、文字、播放条或导航；这些必须由真实 Flutter 组件呈现。

### 日夜应分别成立

浅色模式要有真实的日间配色和光照，深色模式要有能支撑阅读的暗部层次。两者保持主题身份，不以简单加黑或整体滤色代替设计。

动效对象按场景选择，下面仅是方向示例：

| 场景 | 日间可用动态 | 夜间可用动态 |
| --- | --- | --- |
| 森林 / 花园 | 飘叶、花瓣、枝叶随风摆动 | 萤火虫、轻雾、月光下的微摆 |
| 海岸 / 水下 | 水纹、漂浮颗粒、水草与光影 | 发光浮游物、缓慢水流与暗部微光 |
| 城市 / 房间 | 窗光、云影、轻动的帘布 | 远处灯光、窗外雨线、微弱反射 |
| 太空 / 幻想 | 云气、漂浮碎片、缓慢轨道运动 | 星尘、稀疏闪烁、远处光晕 |

白天的浅色粒子常会被亮背景吞没。优先换成有轮廓、有颜色且符合场景的对象，而不是无限提高发光强度。森林日间使用落叶和风、夜间使用萤火虫，是这一原则的例子，并非所有皮肤的固定配置。

## 4. 资源制作与成本控制

背景及绘画装饰可以使用可用的图像生成工具或原创素材，不绑定某个服务商或模型。选定工具后遵循其制作流程，并在资源说明中记录来源。

- 同场景的日夜版本优先在一次图集中制作，保持构图一致；生成时写明分区、顺序与尺寸，按实际返回尺寸裁切。
- 需要多件位图装饰时，按固定网格整套生成和裁切，留足透明边距；不要为每个小部件单独付费生成。
- 图标、纹理线条、粒子和简单形状优先用 SVG、代码或 Rive 矢量制作。位图图集适用于绘画素材，不替代清晰、可缩放的功能图标。
- 背景按实际用途压缩并移除无关元数据。运行包仅放使用中的资源，原始图集、试验帧和视频留在本地制作目录。
- 每个主题保留资源说明：来源、使用许可、裁切和压缩方法、运行资源路径、Rive 画板与状态机、重建方法以及必要的 SHA-256。
- 交付最终选定方案前清理本次试验中被放弃的资源与代码；不擅自删除既有皮肤或用户的其他工作。

先把一个代表性页面放进真实 Flutter 界面检查，再批量制作剩余资源。单独漂亮的场景图不能证明整套界面可用。

## 5. Rive 环境动画

### 资源与接入

环境动态统一通过 `AppSkinAnimationDescriptor.rive` 和共享 `AppSkinRiveAnimation` 接入。可以使用 Rive 编辑器或能够生成兼容资源的制作工具；保留可编辑源文件或可重建脚本，不能只留下来源不明的二进制。

日夜可以使用同一 `.riv` 中的独立画板。画板、动画、状态机命名要明确，自动循环应能由状态机入口直接启动。静态壁纸与透明画板使用一致的构图坐标、缩放方式和锚点。

当前运行入口使用 Flutter renderer；制作后必须在项目实际采用的 Rive runtime 中解码、推进和渲染。不能只凭编辑器、浏览器或文件头判断应用中可用。

### 运动设计

- 动效要在正常亮度、正常手机尺寸下可感知；同时保持文字、封面及控件稳定。
- 主次分明：一到两种主要动态配合少量辅助动态即可；数量、大小、透明度、速度及相位分别控制。
- 重力、风向、漂浮与发光应有依据。叶片可以横移、旋转及翻面，雾缓慢流动，远景比近景更克制。
- 持续循环要检查接缝。落下或飘出的对象应在离开画面或完全渐隐后复位，不能突然从屏幕底部跳回顶部。
- 避免等距、同速、同相位的机械重复。需要随机感时使用可复现的布局和参数，便于回归。
- 静态主场景默认保持稳定。确需整体运镜时，验证裁切、阅读稳定性和持续合成成本，不把整幅壁纸不停缩放作为默认动效。

### 先检查手机裁切

`BoxFit.cover` 会裁掉宽画板两侧。关键粒子、枝叶和锚点必须在目标手机的实际可见区域内；不能只在完整画板预览中看得见。

同时检查高屏、窄屏、横屏和桌面宽窗。避免为了适配一个尺寸，把全部装饰堆到文字阅读区。背景与动画的坐标关系需要一起调整，不能各自独立拉伸。

### 生命周期与失败回退

复用共享控制逻辑，满足以下行为：

| 状态 | 预期 |
| --- | --- |
| 应用内皮肤动画关闭 | 环境动画停止并隐藏；静态场景和主题仍完整可用 |
| 系统减少动画开启 | 环境动画停止，应用内开关不改写系统设置 |
| `TickerMode` 禁用或应用进入后台 | 控制器停止推进，不继续在不可见处运行 |
| 同一资源恢复播放 | 复用已加载的控制器，不反复解码 |
| 资源缺失或解码失败 | 保留静态壁纸与后备底色，界面和操作正常 |
| 卸载或更换动画资源 | 释放旧资源，过期异步加载不能覆盖新状态 |

皮肤动画开关只影响皮肤环境；页面转场、歌词、骨架、标签与播放器动画仍按各自规则和系统减少动画设置运行。

## 6. 材质、透明度与界面风格

Material 与 Cupertino 共享场景、配色和业务状态，但保留各自 SDK 控件及设计语言。不增加第三方玻璃渲染库，不通过伪造 `ThemeData.platform` 切换风格。

- 壁纸皮肤的 MiniPlayer 为独立浮动卡片，底部 Tab 为全宽导航；两者使用带主题底色的半透明磨砂，播放卡片通常比导航更浓。
- 透明度以实际阅读和场景透出效果为准，日夜分别调节。不要把某一个皮肤的数值作为所有皮肤的标准，也不要把表面不透明度和文字不透明度一起降低。
- 当前 `AppSkinTheme` 已统一将壁纸 MiniPlayer 配置不透明度乘 `0.90`、导航乘 `0.85`。新皮肤应按最终生效值设计，避免在组件中重复相乘。共享策略将来调整时以实现为准。
- 纯色皮肤保持不透明，关闭无效背景模糊。弹窗外壳保持稳定的不透明底色。
- 模糊裁切在各自控件边界内，每个区域保留一层有效滤镜；卡片外的间隙透出清晰场景，避免整页模糊。
- 列表视口延伸到屏幕底部，让内容从播放卡片与导航后方滚动；通过列表末尾留白避让最后一项，不在列表外整体缩短视口。
- 透明壁纸页面的 Cupertino 普通顶栏跟随页面透明，不额外叠白条和背景模糊；实色页面保留正常底色。
- “显示内容背景”控制普通内容表面，包含 Cupertino 设置分组和功能入口；搜索输入、MiniPlayer、底栏和弹窗使用独立控制表面。
- 不因增加装饰破坏安全区、键盘避让、返回值、滚动位置、输入焦点或播放状态。精确尺寸与弹层规则参见现有界面规范。

## 7. 在本项目落地

先读现有实现，再决定最小必要扩展。可参考森林的分层和资源流程，但不要复制主题名称、枝叶纹理或日夜参数到无关风格。

| 位置 | 用途 |
| --- | --- |
| `lib/app/theme/skins/<skin_id>_skin.dart` | 新皮肤包：元数据、明暗配置、图标与背景动画描述 |
| `lib/app/theme/skin/app_skin_models.dart` | 共享皮肤模型；仅在现有能力确实不足时扩展 |
| `lib/app/theme/skin/app_skin_registry.dart` | 注册内置皮肤，核对 `builtIn`、`withCustom` 及 ID 集合 |
| `lib/app/theme/skin/app_skin_background.dart` | 全局场景、静态遮罩与动画层 |
| `lib/app/theme/skin/app_skin_rive_animation.dart` | 统一加载、播放、暂停、恢复和销毁 |
| `lib/app/theme/skin/app_skin_theme.dart`、`app_skin_surface.dart` | 共享材质、底部表面及内容底色规则 |
| `lib/app/theme/skin/app_skin_icon.dart` | 角色图标和 SDK 回退 |
| `lib/app/i18n/app_i18n.dart` | 皮肤名称、介绍等本地化 |
| `assets/skins/<skin_id>/` | 日夜场景、`.riv`、图标、真实缩略图和资源说明 |
| `scripts/` | 必要的资源重建脚本；制作工具和缓存不进入运行依赖 |
| `test/app/theme/skin/`、`test/app/theme/skin_preview_golden_test.dart` | 资源、运行行为、共享表面及真实界面预览 |

新增资源同步声明到 `pubspec.yaml`，新增皮肤同步注册、配置兼容及相关测试。高频使用的主题图标覆盖主导航、搜索、播放 / 暂停、队列、收藏等角色；其余角色保留清楚、完整的 SDK 回退。

共享层优先解决跨页面需求，不复制一套主题专用首页。装饰尽量封装在主题和共享表面中，不在每个业务页散落皮肤 ID 判断。

## 8. 性能与发热验证

Rive 是本项目约定的环境动画方案，不代表自动省电。时间轴 `30 fps` 也不等于运行时只绘制 30 次；文件小、动画顺滑、单次帧耗时短，都不能单独证明持续运行不发热。

制作时把静态场景与动画绘制范围分开，合理使用重绘隔离，避免环境帧或播放进度导致整个业务页面重建。高频监听放在最小消费组件，沿用 Riverpod `select` 等现有规则，不为减少重建缓存过期业务状态。

性能验证使用真机 Profile 模式，并带上项目配置：

```sh
flutter run --profile -d <device-id> --dart-define-from-file=.env
```

先检查帧耗时和重建范围，再检查持续运行的功耗、温升及电量变化。动画开 / 关对照应使用一致的设备、亮度、刷新率、歌曲、播放状态、滚动操作和运行时长，记录测试条件及结果。已有人工验收包含连续滚动、切歌与队列开关等场景，应与环境动画一起检查。

出现发热时先定位是环境动画、滤镜合成、重复绘制还是业务负载，再优化。不要未经说明就把用户已经接受的效果悄悄削弱；需要做明显视觉取舍时提供实际对照。没有真机结果时，明确写明尚未验证，不能用浏览器帧导出或组件测试替代。

## 9. 制作与交付流程

1. **确定方向。** 根据用户风格形成主题说明、日夜差异、视觉母题和动画对象，明确默认范围或当次例外。
2. **制作一套场景。** 优先图集完成主画面，接入真实首页，核对裁切、内容区、配色与阅读。
3. **补齐整套材质。** 统一搜索、列表、详情、设置、MiniPlayer、导航和图标；检查内容底色开关。
4. **制作 Rive。** 日夜分别选择符合场景的动态，使用共享入口；检查实际可见性和完整循环。
5. **检查真实页面。** 两种界面风格 × 日夜模式；至少包含首页、长列表 / 详情和设置，检查底部透明度和大字号。
6. **验证交互与成本。** 测试生命周期、回退、切换时状态保留、重建范围及真机表现；记录未完成项。
7. **整理交付。** 更新真实缩略图、动图 / 视频、资源说明和重建源，清理本次废弃试验；提交与推送按用户授权执行。

预览必须来自真实 Flutter 页面，使用固定示例数据并等待壁纸、Rive 和字体加载完成。动态视频应包含日间和夜间，注明导出尺寸和采样帧率；它是视觉预览，不是真机性能报告。

优先使用 `Makefile` 中的检查入口；代码改动执行 `make analyze` 和适当回归，提交 PR 前执行 `make test`。代理环境若提供专用 Dart / Flutter 测试工具，遵循工具要求调用对应测试。`make skin-previews` 用于更新已有皮肤基线，新主题应补齐其导出用例；更新既有缩略图时同步资源说明与校验记录。测试超时或只跑了部分用例，要如实说明。

可参考 [森林资源说明](../assets/skins/forest_sanctuary/README.md)、[森林资源生成脚本](../scripts/generate_forest_ambient.mjs) 及 [城市声场资源记录](../assets/skins/city_sound_creator/LICENSES.md)。具体文件参数只用于理解实现，不作为新主题的固定模板。

## 10. 完成验收清单

- [ ] 主场景、材质、图标和环境动态具有统一的主题身份，普通页面延续同一世界。
- [ ] 日间与夜间都独立成立，动画对象合理，正常手机尺寸下都能看到主要动效。
