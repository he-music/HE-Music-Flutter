# 歌曲列表分页与播放队列

## 行为约定

接口没有列表版本号，采用页面当前数据为准的简单规则：每次点击整列表播放（包括点击某一首），用页面当前已加载的歌曲及分页游标一起替换播放队列。不按数量取最大值，也不合并上一次播放的数据。

- 播放器已有 2000 首，重新打开页面只加载了 1000 首，再点击播放会替换为 1000 首。
- 页面加载到 2000 首后点击第 1500 首，会使用这 2000 首并从第 1500 首开始。
- 刷新后列表从 1000 首减少至 900 首，再点击播放会使用新的 900 首。
- 批量选择后播放只包含选中的歌曲，不自动加载原列表的其他歌曲。
- 页面继续翻页不会自动修改已经开始播放的队列；再次点击页面歌曲时才用页面数据替换。

页面按滚动分页。播放器独立持有分页信息，在剩余待播歌曲不超过 3 首时预取下一页；后台播放无需原页面存活。补足后停止，接近新的队尾时再请求。`hasMore=false` 后沿用既有播放模式。

歌曲数量本身提供手动加载全部入口，覆盖歌单详情、用户歌单详情、排行榜、新歌列表和歌手歌曲。还有下一页且总数可用时显示 `1000/2000 首` 加向下图标；总数未知时显示 `1000 首` 加向下图标。点击后逐页加载，加载中保留紧凑数量并显示 Spinner，失败保留数量并显示重试图标。完成后显示实际已加载的 `2000 首`，去掉图标和点击行为。完整操作说明放在 tooltip 和无障碍标签中，不占用可见文字空间。

元信息入口不会新增页面行高或操作按钮；无顶部详情区的新歌页使用标题栏右侧的空白区域显示数量，不挤压原操作栏。手动全量加载由页面控制器管理，折叠顶部不会中断；刷新、切换数据来源或离开页面后停止继续请求。已经发出的请求仍按原有防过期逻辑处理。

有限歌曲列表不使用电台的 1000 首滚动窗口，不删除已加载的队首歌曲。随机模式按已加载歌曲的遍历进度补页，新页加入后续遍历；不承诺尚未加载歌曲与已有歌曲具有全列表均匀随机概率。

## 页面范围

| 页面 | 处理 |
| --- | --- |
| 歌单详情 | 分页游标交给播放队列 |
| 用户歌单详情 | 同上，歌曲保留各自平台 |
| 排行榜详情 | 同上，保留 `last_id` 游标 |
| 新歌列表 | 同上，固定开始播放时的平台及标签 |
| 歌手详情歌曲标签 | 移除连续全量加载，支持滚动分页和播放续载 |
| 歌手详情专辑、视频标签 | 移除连续全量加载，支持滚动分页和失败重试 |
| 推荐歌曲详情、专辑详情 | 当前歌曲接口不提供分页，保留一次返回的列表 |
| 搜索歌曲、歌词搜索 | 当前点击为单曲插播，不转成整搜索结果队列 |
| 本地曲库及下载、收藏、历史 | 保留各自现有的数据加载及播放语义 |

## 实现边界

`SongListPagination` 随 `PlayerQueueSource` 保存，因此当前队列和“上个队列”均能保留下一页信息，旧存储记录没有该字段时仍可读取。音频层复用各页面的 API 客户端，避免排行榜、用户歌单等接口的解析规则发生分歧。

同一队列的预取、手动下一曲、播放完成共用请求；每次替换队列都会使旧请求失效，即便重新选择的是同一个列表。失败不推进页码，预取失败不打断当前播放；到队尾可重试。空页但 `hasMore=true` 视为异常，重复歌曲按平台与 ID 去重，重复页的跳过次数有上限。

无服务端快照版本时，播放期间服务端插入、删除或重排歌曲仍可能使页码分页漂移。去重只能避免重复项；刷新页面并重新播放可更新队列，不声称实现实时列表同步。

本次仅调整分页和播放行为，沿用歌手页面现有材质及布局，不新增玻璃表面或高频播放状态监听。
