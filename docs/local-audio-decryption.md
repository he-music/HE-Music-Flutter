# 本地音频解密

在线歌曲请求在原生端协商 `client_decrypt=true&audio_params_version=1`。后端准备执行材料，客户端直接访问 CDN，并按 `audio_params` v1 执行变换；没有执行参数的响应继续使用后端返回的音频地址。旧的原始 `key` 响应拒绝执行，避免将密文当作可播放音频。

## 播放

`SongAudioSource` 统一校验播放和下载的地址解析结果。`DecryptingAudioSource` 继承 just_audio 的 `StreamAudioSource`，通过 `request(start, end)` 直接请求 CDN、解密并返回 `StreamAudioResponse`。它不启动 HTTP 服务，不生成独立的 loopback 会话地址；解密执行材料保存在音源对象中，不进入媒体元数据。

关闭自动缓存时，播放器直接使用 `DecryptingAudioSource`。开启缓存且允许写入时，`LockCachingAudioSource.streamSource` 直接消费它的响应流，只有外层缓存音源注册到 just_audio 的代理。因此两条在线播放路径都只经过 just_audio 自带的一层本机 HTTP，缓存和解密之间没有额外 HTTP 请求。完整缓存命中仍直接播放本地文件。

kind 1–3 按实际上游响应的字节偏移解密，工作 isolate 接收有背压的分块数据；首包立即输出，后续数据合并分块以减少通信开销。CDN 忽略 Range 并返回 200 时从零开始解密，返回完整响应且不声明部分响应偏移；206 必须有合法且长度一致的 Content-Range。kind 4 先取得完整 MP4，在工作 isolate 解密后通过文件读取返回指定范围。单个 MP4 输入上限 128 MiB，完整文件解密串行执行，每个音源最多持有四个上游读取请求；输入上限不等于进程峰值内存上限。

解密音源归播放音源租约所有。释放顺序为原生播放器脱离音源、取消缓存和 CDN 读取、释放解密工作文件、释放缓存和音源注册。返回后尚未消费的流也由音源负责释放。MP4 临时工作目录随音源释放清理；新进程首次使用该目录时清理上次异常退出留下的文件。

当前方案仍依赖 Dart 在后台及时执行，单层代理不等于后台稳定性保证。先通过真机锁屏、弱网和长时间播放验收；若仍有供流卡顿，再评估 Android Media3 DataSource 与 Apple 资源加载代理的原生实现。

## 缓存设置

- “播放时自动缓存”只控制新增持久缓存。关闭后仍能读取已有完整缓存，也能解密在线播放。
- 蜂窝网络设置只控制蜂窝网络上的自动缓存写入。
- 缓存策略按音源选择时的快照生效，不因中途切换设置强制重载当前歌曲。
- 持久缓存保存解密后的完整音频。kind 4 关闭自动缓存时仍需要临时工作文件，这些文件不发布为可复用缓存。
- 缓存标识保留平台、歌曲、请求音质和请求格式。扩展名、MIME 和元数据使用实际输出格式，额外允许 `kuwo mflac → flac` 与 `soda aac/flac → m4a`，拒绝其他不匹配。

## 下载

系统后台下载器直接下载 CDN 文件，不依赖本机供流服务。加密下载先写入暂存文件，下载完成后执行本地解密；只有明文文件准备完成后才能写入标签、发布到下载列表或移动到公开下载目录。待解密阶段和执行材料在应用私有任务存储中记录，以便恢复；错误和日志不包含执行材料。

公开目录移动与应用任务日志无法跨进程原子提交。移动前保留私有明文源文件，恢复时可以重试发布；若进程恰好在系统移动成功、目标路径尚未写入日志时退出，公开目录可能留下重复的明文副本。删除任务会先等待当前发布完成，再按返回的目标路径清理。
主动下载独立于播放缓存设置。系统后台下载可以在应用挂起时继续；本地解密依赖应用获得执行时间，不能保证 iOS 在暂停播放后立即完成解密。

## 验证

算法来源、同步方式及 Go 对照向量见 [执行器说明](../lib/core/audio/decrypt/README.md)。自动化测试覆盖参数校验、流式偏移、MP4 样本、缓存开关、格式兼容、任务恢复及流式音源释放。真实 CDN、平台音频解码和后台稳定性还需在 Android、iOS、macOS 设备上验证，重点包含锁屏、弱网、拖动进度、快速切歌和解密期间退出后恢复。
